# 분석 화면 성능 개선

2026-11-05, 원본 데이터·MOS 계산식·품질 경계·위치 선정 방식은 유지한다.
직전 날짜 자동 선택 수정과 전체 기간 조회 기능도 유지한다.

## 변경

- 시간대별로 전체 통화를 24번 필터링하던 집계를 한 번의 시간대 분류로 변경했다. 중복 ID 처리, 원본 순서, 알 수 없는 시각, 시간대별 고객 경험 판단은 기존 결과와 동일하다.
- 목록의 고객·날짜 메타데이터를 데이터셋당 한 번 인덱싱한다. 첫 일치 항목을 반환하던 의미와 원본 객체를 보존한다.
- 검색어를 입력할 때 같은 통화 목록을 재정렬하지 않는다. 정렬 결과를 재사용하고 검색·SIP 조건만 적용한다.
- 데이터 요청을 결합하고 성공 결과만 30초간 보관한다. 상한은 목록 2개, 일별 요약 5개, 데이터셋별 고객 상세 8개다. 취소·실패·원본 버전 불일치는 저장하지 않는다. 각 호출자의 취소는 독립적이며 HTTP 재검증은 유지한다.
- 기존안의 화면별 결과 캐시는 최근 두 개로 제한한다. 기간 조합마다 큰 결과를 계속 보관하지 않는다.
- Leaflet 이벤트는 최신 선택 함수를 참조한다. 부모의 검색·상세 로딩으로 함수만 바뀔 때 지도 레이어를 재생성하지 않는다. 좌표·선택 스타일·측정 지표·팝업 유무가 바뀔 때는 필요한 갱신을 유지한다.

## 측정

원본 5일 184,232통화, 같은 프로세스에서 구·신 구현을 번갈아 7회 실행한 중앙값이다. 파일 읽기와 JSON 파싱은 제외한다. 세 함수의 전체 JSON 출력 SHA256이 기존 구현과 일치했다. PC 상태에 따라 시간은 달라진다.

| 집계 | 이전 | 이후 |
| --- | ---: | ---: |
| MOS·고객 체감품질 | 751.43ms | 506.91ms |
| 시간대 통화 | 156.31ms | 55.58ms |
| 통화 요약 | 84.35ms | 64.91ms |

목록 메타데이터 46,640고객·85,302개 고객별 날짜에서 1,000회 조회한 중앙값은 전체 순회 1,493.65ms, 인덱스 조회 0.18ms였다. 인덱스 최초 생성은 48.95ms였으며 조회 수치에 포함하지 않았다. 이 수치는 화면 전체 응답 시간이 아니다.

요청 수 검증에서 같은 목록 두 번 조회는 2→1회, 5일 전체 두 번 조회는 10→5회, 같은 고객 상세 두 번 조회는 2→1회였다. 콜백만 4번 바꾼 지도 회귀 검증에서 레이어 생성은 5→1회가 됐다.

## 로컬 빌드

`npm.cmd run build:local`은 public 데이터 경로 약 15만 개를 서버 코드에 삽입하거나 매번 복사하지 않는다. 로컬 모드를 명시한 빌드에서만 루프백 미리보기 서버가 원본 `public` 파일을 직접 제공한다. 원본 파일과 같은 바이트를 전송하고, HEAD·ETag·Last-Modified 재검증을 지원한다. 데이터 경로를 벗어나는 요청과 숨김 파일은 차단한다. 기본 `npm.cmd run build` 동작은 유지한다.

같은 PC에서 직전 기본 빌드는 약 14분, 새 로컬 빌드는 168.83초였다. 서버 시작 파일은 12,573,816바이트에서 206,876바이트로 줄었다. 전체 빌드 시간은 파일 캐시와 PC 부하에도 영향을 받는 단일 실행 관찰값이다. 로컬 빌드와 함께 원본 `public` 폴더를 유지해야 한다.

## 검증 범위

분석 테스트, 품질현황 테스트, 새 최적화 회귀 테스트, 타입 검사와 수정한 앱·설정 파일의 린트 검사를 실행한다. 전체 `npm run lint`에는 미변경 CommonJS 테스트의 ESM 규칙과 다른 UI의 접근성·React 규칙 오류가 남아 있으므로 전체 저장소 린트가 통과했다는 의미는 아니다.
