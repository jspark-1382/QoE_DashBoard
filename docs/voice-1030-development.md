## MOS 평가 기준

- 불량: `1.0 <= MOS < 3.0`
- 주의: `3.0 <= MOS < 3.5`

- 미평가: 원본 `_`, null, NaN, 허용 범위를 벗어난 값

### BYE Cell 기지국 대체 매핑 (2026-11-03)

### 행정동 경계 위 통화 위치 마커

- **모든 통화에 동일한 CDR 종료 시각(BYE 대용) 기준** 적용. 원본 CDR END TIME 이전 마지막 유효 GNSS 좌표를 우선 사용하고, 없을 때 유효 무선 추정을 사용합니다. 60초 이내 좌표만 채택하고 소스 시계 오차 ±1초 범위의 종료 직후 관측은 허용합니다. 종료 기준 대표 좌표는 통화당 최대 1개이며 행정동 중심점으로 대체하지 않습니다.
- 빨간색 숫자 마커는 GNSS 관측(측정 정확도 정보는 미제공), 주황색 숫자 마커는 무선 기반 추정(정확도 미검증)을 나타냅니다.
- 약 1m 안에 겹친 좌표는 한 마커에 묶어 통화 건수를 표시합니다. 마커 클릭 시 통화 시각·원본 MOS(v5)를 확인하고 개별 통화 분석으로 이동합니다.
- 2026-10-30 데이터 기준 신규 LTE RU+Cell 목록 적용 후 MDT 위치 후보 통화 95건 중 종료 시각 기준으로 91건(통화당 대표 위치 1개)이 사용됐습니다. 나머지 4건은 종료 시각과의 차이가 60초를 초과해 보류했습니다. 개포1동에는 종료 위치 기준 26건이 배정됐으며 **여러 행정동을 지나간 통화를 중복 집계하지 않습니다.** 원본 이동경로는 고객·통화 분석에 그대로 남습니다.
- **통화 전체의 MOS(v5)만 있으므로 특정 좌표에서 MOS가 순간적으로 떨어졌다고 단정할 수 없습니다.** 이 마커는 저MOS 통화가 연결된 관측 또는 추정 위치입니다.

### 2026-11-03 고객·통화 지도 출처 구분 및 통화 시간 개선

고객·통화 분석의 통화 목록에서는 원본 소수 초를 화면에 그대로 노출하지 않고 1초 단위 반올림(분:초, 1시간 이상은 시:분:초)으로 표시합니다. 원본 소수 초 데이터와 계산 값은 변경하지 않습니다. 표시 시간 셀의 툴팁에는 원본 값을 소수 셋째 자리까지 확인할 수 있습니다.

고객·통화 지도에서 위치 근거를 고정된 색상·모양으로 구분합니다: GNSS 관측=청록 원, 다중 RU 무선 추정=보라 마름모, 보간 추정=주황 마름모, 기지국=회색 삼각형. 품질 선택 지표의 기준 미달은 빨간 테두리로 구분합니다. 다른 행정동·기존 대시보드 지도 색상은 변경하지 않습니다. 선택 통화의 GNSS/무선 추정/보간/기지국 건수를 지도 앞에서 보여주고, 선택 관측 근거 패널에도 관측 또는 추정 여부를 함께 표시합니다. GNSS 관측이 0건이면 고객 위치는 실측이 아닌 계산된 추정 좌표임을 경고합니다.

검증: scripts/tests/contract-ui-readability.test.cjs, npm.cmd run test:analyst, TypeScript·oxlint, npm.cmd run build.

### 2026-11-12 대용량 자료 조회 개선

기본 품질 현황과 고객 선별 화면은 로컬 조회 서버에서 집계한 요약만 받습니다. 기존 XLSX와 원본 JSON은 그대로 보존하며, 같은 리비전의 SQLite 조회 저장소를 `outputs/voice-query-data/`에 별도로 생성합니다. 데이터 파일과 조회 저장소가 서로 다른 리비전이면 오류를 표시하고 갱신을 요청합니다.

- 품질 현황: 최초 요청은 메타 정보와 요약뿐입니다. 지도는 요약 표시 후 지도 영역이 화면에 보이면 자동으로 조회합니다. 통화 목록은 버튼을 눌렀을 때 조회하고, 원본 관측 파일은 통화를 선택할 때 읽습니다. 지도·상세 분석 코드도 나중에 받습니다.
- 고객 목록: 서버 검색과 페이지별 25명 조회를 사용합니다. 전체 고객 수와 선택한 고객의 집계는 페이지에 있는 행 수와 별도로 계산합니다.
- 고객 선별: 서버에서 전체 모집단의 순위·필터·통계를 계산합니다. 요약 표시 후 지도 영역이 보이면 지도가 자동으로 열리며, TOP 10 경로는 해당 지도 모드를 선택했을 때 조회합니다.
- 고객·통화 분석: 선택한 고객의 날짜 목록과 원본 통화 자료만 받습니다. 전체 고객 명세나 전체 날짜별 통화 파일을 내려받지 않습니다.
- CSV: 요청한 필터 전체를 서버에서 순차적으로 내보냅니다. RTP·무선 지표는 실제 원본에서 읽으며, 내보내는 작업은 화면 조회와 별도 실행됩니다. 대량 CSV는 파일을 읽는 시간이 필요합니다.

최초 접속 실측(로컬 Chrome, 캐시 비활성, 반복 확인): 요약 표시 약 4~6초, 분석 데이터 전송 약 19KB. 이전 기본 접속의 약 639MB 및 전체 기간 약 2,051MB 다운로드를 제거했습니다. 지도 열기 후의 자료는 전체 기간 기준 약 2MB입니다. 측정 환경에 따라 시간은 달라집니다.

검증된 전체 기간 값: 통화 1,490,033건, 고객 268,182명, 평가 가능 1,088,738건, 저품질 9,315건. 원본에 있는 전체 1,490,033건의 점수를 그대로 유지했으며, 지도 GPS 673건·삼각 측량 426건·관련 기지국 449곳도 일치합니다.

조회 저장소만 생성/검증할 때는 `npm run data:voice-query`, 원본 추가 후 전체 갱신은 `npm run data:all`을 사용합니다. 전체 갱신은 게시 전에 같은 리비전의 조회 저장소까지 준비합니다. 화면 실행은 `scripts/start-qoe.ps1 -NoBrowser` 또는 기존 실행 바로가기를 사용합니다. 개발 서버에도 같은 로컬 API가 연결됩니다. Node.js 22.13 이상이 필요합니다.

검증 근거: `scripts/tests/voice-query-api.test.cjs`, `scripts/tests/server-*.test.cjs`, `scripts/tests/quality-summary-panels.test.cjs`, 실제 자료 감사 및 `outputs/server-query-qa/result.json`의 브라우저 기록.

### 2026-11-12 고객 선별·개선후보 추가 최적화와 연속 불량

기존 UI를 유지하며 기본 고객 선별 집계를 조회 저장소에 미리 준비했습니다. 사용자 조건이 달라지면 해당 조건으로 계산하되, 같은 범위의 순위·상세·지도 결과는 제한된 캐시에서 재사용합니다. 개선후보 지도는 전체 149만 통화를 먼저 훑지 않고 실제 위치 1,947개에서 통화를 연결합니다. 개선후보 화면에서 사용하지 않는 품질 요약 조회를 제거했으며, 모델 전환 시 격자·RF·모델 보고서·기지국 자료를 다시 받지 않습니다. 고객 선별과 일반 조회는 별도 작업 경로를 사용하고, 닫힌 화면의 대기 중 조회는 실행하지 않습니다.

연속 불량 고객은 같은 시작시각이 있다는 이유만으로 전체 값을 미확정으로 만들던 조건을 수정했습니다. 각 시각 그룹의 모든 가능한 순서에서 판정이 같은지 검사하고, 통화 ID나 건수는 합치거나 줄이지 않습니다. 역사 데이터의 71명은 재현되며 전원이 현재 전체 기간(10/26~10/30) 529명에 포함됩니다. 날짜별 값은 84·124·90·101·109명입니다. 실제 순서에 따라 판정이 달라지는 입력은 계속 미확정으로 취급합니다. 카드와 고객군 필터는 동일한 판정 함수를 사용합니다.
