# 개선 후보 지역별 AI 분석 및 점검 SOP

## 화면과 사용 순서

품질 현황의 **개선후보**에서 후보 행 오른쪽 **AI 분석**을 누릅니다. 해당 후보가 선택되고 서버 근거 수집 → Qwen 분석 → 검증을 거칩니다. 일반 지도와 지도 전체화면에서 같은 기능을 사용합니다. DBSCAN과 다섯 대안 모델을 지원합니다.

후보 팝업은 왼쪽에 실제 POT 지도와 동일 날짜·대역의 25m 비교 지점을, 오른쪽에 우선 조사 제목과 다섯 원인별 조사 항목을 표시합니다. 항목을 펼치면 같은 실행의 조사 이유, 확인 항목, 부족한 자료와 원본 통화가 보입니다. 집계 근거와 Qwen 가설은 각각의 출처로 표시합니다.

최근 저장 결과는 **최근 결과 / 이전 1 / 이전 2** 작은 탭으로 비교합니다. 선택 대상의 상세 근거·확인 항목과 전체 보고서를 펼치면 관측, 원인 가설과 같은 가설에 연결된 확인 절차·조건부 개선·개선 후 검증을 볼 수 있습니다. 근거 없는 분류는 다른 분류의 대상을 남기지 않고 해당 분류의 부족한 자료와 확인 항목을 표시합니다.

가설의 조치 보기 버튼은 해당 원인의 개선 카드로 이동합니다. 근거 펼침과 원본 통화 상세 연결은 유지되며 새로 Qwen을 호출하지 않습니다. 팝업을 닫아도 기존 지도 전체화면과 후보 목록을 유지합니다.

## 분석 대상과 통계

후보는 고객 분석과 구분되는 `kind: candidate` 대상입니다. 후보 ID, 자료 버전, 날짜·매일 시간 범위, 발견/평가 구분, 실제 군집 모델, 위치 정책과 scopeKey를 받습니다. 브라우저의 통화 목록이나 집계값은 받지 않습니다.

서버는 공개 산출물의 index → summary/detail 또는 모델 report를 통해 후보와 구성 통화를 찾고, SQLite의 고객·날짜·시간·저품질 조건과 다시 대조합니다. 다른 자료 버전·조작된 후보·잘못된 연결·잘못된 경로는 거절합니다. 산출물 내용·구성 통화 집합·근거/프롬프트/SOP 버전을 결과 지문과 재사용 키에 포함합니다. 수집 이후와 모델 응답 이후에도 조건이 바뀌지 않았는지 확인합니다.

**전체 통계는 후보 구성 집단 전체**입니다. 상세 무선·RTP는 최대 32개 대표 통화를 이용하며 무작위 표본이 아닙니다. 표본 선정은 Drop, 날짜·대표 Cell, 낮은 QoE를 우선합니다. 측정 행 수와 독립 통화·고객 수를 구분하고 통화별 대표 평균에 동일 가중치를 적용합니다.

현재 후보 산출물에는 동일 지역·시각·위치 확보 정책으로 선정한 정상 비교군이 제공되지 않습니다. 정상 통화는 `null / 미산정`으로 표시합니다. 같은 고객의 기간 전체 통화를 지역 정상 분모로 사용하지 않으며, 후보 구성 집단의 저품질 비중을 지역 전체 불량률로 표시하지 않습니다.

후보 구성 위치, 통화에 연결된 MDT 측정, 별도 측정일의 25m 배경 격자를 구분합니다. Top1은 측정 행 수가 가장 많은 대역입니다. 표시 반경과 최대 점간 거리는 위치 정확도 또는 실제 저하 순간 위치가 아닙니다. 현재 군집 알고리즘·품질 정책을 수정하지 않습니다.

## SOP 초안과 AI의 역할

SOP 템플릿은 `scripts/qwen-candidate-sop.cjs`에서 관리합니다. 회사 승인 절차가 아닌 **조회용 점검 SOP 초안**입니다. 담당자·완료 체크·현장 메모·조치 이력은 제공하지 않습니다.

서버가 범위 검토, 정상 비교군, 무선/RTP 자료와 Drop 관측에 따라 적용할 절차와 순서를 정합니다. 범위 검토가 필요하면 구간·위치 확인을 앞에 배치하고, 일반 후보에서는 비교 자료 충분성부터 확인합니다. 통화 매칭 무선·RTP가 있을 때 관련 점검을 추가하고, Drop이 관측된 후보에 SIP 점검을 추가합니다. 마지막에는 현장 보완 측정과 별도 날짜의 개선 후 검증을 제시합니다.

각 템플릿은 확인 대상 종류, 지금 확인할 일, 조건별 개선 방향, 개선 후 검증을 서버 소유 필드로 제공합니다. 가설은 명시적인 sopIds로 허용된 템플릿과 연결하며, 제목 문자열을 추측해서 연결하지 않습니다. 예를 들어 확인된 전송 구간의 오류 링크·장비는 복구 방향을, 확인된 IMS 장애는 해당 서비스·연동 구간의 복구 방향을 제시합니다. 현재 원인이 확정됐다는 뜻은 아니며 조건을 확인한 뒤 적용하는 조치안입니다.

Qwen은 후보의 관측 패턴과 해당 절차의 필요성을 짧게 설명합니다. 공통 자료 확인 절차는 접어서 제공하고, 3단계에는 원인별 개선과 검증을 우선 표시합니다. 임의의 장비 조정 수치나 실행 명령은 생성·실행하지 않습니다. 향후 회사 SOP로 템플릿을 대체할 수 있습니다.

구조·근거 ID·SOP ID·숫자·빈 응답·잘린 응답·응답 모델을 검증한 결과만 완료로 처리합니다. 기존 고객 분석의 백분율·음수·빼기식 숫자 검증은 그대로 사용합니다. 이 검증은 문장 구조와 근거 연결을 확인하며, AI 원인 가설의 인과적 타당성을 증명하지 않습니다.

가설이 실제 서버 대상 ID를 명시했고 제공한 모든 근거 ID도 그 대상들에 속할 때, 중복 성격인 대상별 근거 연결이 빠졌다면 같은 서버 대상의 실제 전송 근거 ID로 연결만 보완합니다. 다른 대상의 근거를 삭제·대체하거나 가설·관측 문장을 고치지는 않습니다. 보완한 ID는 `referenceResolution`에 기록하며 실제 Qwen 응답 원문은 그대로 보존합니다. 숫자·관측 의미·원인 단정 검증은 보완 후에도 동일하게 적용합니다.

## 결과와 실패 처리

기존 `/qoe/api/analysis/jobs` 비동기 생성·조회·취소 API를 재사용합니다. 후보 작업은 수집/분석 단계를 표시하고 추정 진행률을 만들지 않습니다. 기본 동시 2개·대기 6개, 서버 결과 40개·30분 한도를 유지합니다.

같은 후보 조건·서버 산출물·모델 설정의 활성 작업은 재사용합니다. 완료 결과는 열람할 때 재사용하고, **전송**은 현재 프롬프트로 새 Qwen 분석을 실행합니다. **프롬프트 수정**에서 실제 전송 문장을 편집할 수 있습니다. 실패·취소 후에도 새 작업으로 다시 실행할 수 있습니다. 실패해도 이미 수집한 통계와 이전 저장 결과는 남습니다. 후보별 세션을 분리하여 늦은 응답이 다른 선택 후보로 섞이지 않게 합니다. 조건이 바뀌면 재분석 필요를 표시합니다.

완료 결과와 비밀값을 제거한 실제 입력·응답 기록을 `outputs/candidate-ai-analysis/`에 후보 조건별로 최근 **3개** 보관합니다. 같은 후보 ID뿐 아니라 자료 버전·날짜·시간·분석 범위·위치 정책·군집 모델까지 일치하는 결과끼리 비교합니다. 네 번째 완료 결과를 저장하면 가장 오래된 결과와 그 실행 기록을 함께 교체합니다. 실패·취소한 분석은 성공 이력을 밀어내지 않습니다. 저장 성공·실패는 화면에 별도로 표시합니다.

새로 고침·팝업 닫기·로컬 분석 서버 재시작 후에도 저장 결과를 불러올 수 있으며 이력 조회·선택은 Qwen을 호출하지 않습니다. 화면이 사라져도 서버 분석은 계속되어 완료 결과를 저장합니다. **분석 취소**를 누른 경우만 명시적으로 중단합니다. 메모리 작업의 30분 만료와 영구 저장 이력은 별개입니다. 현재 연결 계약은 candidate-evidence-v7 / candidate-prompt-v10 / candidate-sop-draft-v7입니다. 이전 버전도 당시 근거와 연결된 보고서는 열람할 수 있으나 새 형식의 분석을 대신해 재사용하지 않습니다.

저장 이력을 읽을 때 현재 원본·후보 산출물·실효 모델 설정과 다시 대조합니다. 달라진 결과는 과거 조건으로 표시하고 재사용하지 않으며, 당시 보고서와 원문은 계속 열람할 수 있습니다. 현재 지도 자료가 없거나 자료 버전이 바뀌어도 저장된 분석 본문을 숨기지 않고 지도 미확보 상태를 별도로 보여줍니다.

## 담당자의 조사 판단을 돕는 검토

현재 원인 카테고리는 커버리지 부족, 주파수·용량 부족, 셀 중첩·간섭, 셀·주파수 전환, 장비·전송·단말 이상입니다. 용량은 셀 자원 자료가 필요하며, 종료 원문은 최초 중단 구간을 찾는 단서입니다. 과거 저장 보고서는 당시 분류를 유지합니다.

현재 v10 기본 자동 분석은 원인 가설과 조사 제안을 함께 반환합니다. 원인 가설은 현재 다섯 분류 안에서 실제 전송 대상의 허용 분류·근거·동일 분류 SOP에 연결되며 최대 5개입니다. 원인이 가능한 실제 관측이 있으면 빈 가설만 반환한 응답을 한 번 보정합니다. 자료가 부족한 분류를 억지로 채우지 않습니다. 이전 저장본은 과거 결과로 계속 열람합니다. 사용자 수정 프롬프트의 원문 전송과 근거·숫자·분류·SOP 검증은 유지합니다.

운영 기준은 DL RSRP ≤ -100, UL 원본 PHR ≤ 3, 같은 통화의 30초 창에서 실제 서빙 PCI 또는 Cell-ID 변경 3회 이상입니다. 둘 다 같은 경계에서 바뀌면 한 번만 세며 A→B→A→B는 세 번입니다. 이웃 PCI 개수·표본 세 개·주파수 변경만으로 Pollution을 만들지 않습니다. 원본 시각 공백·상충 중복·시각 기준 불명은 분리하고, 실제 변경 창과 사건 시각을 표시합니다. 원본 측정행의 PCI 열을 사용하며 이웃 PCI로 대체하지 않습니다.

통화별 `call-criteria`는 최대 32개 원본 상세 표본 전체의 DL·UL·전환 기준과 결측 상태를 유지합니다. POT에는 실제 -100 기준 이하 분포와 원본 PHR 평균을 사용합니다. **PHR 평균 ≤ 3과 개별 PHR 측정값 ≤ 3은 별도 집계**이며, 평균을 개별 충족 횟수·비율로 바꾸지 않습니다. PHR 원본 단위·실제 유효 분모는 미확인으로 표시합니다. 조건 충족은 원인 후보 선정 근거이며 인과 확정이 아닙니다.

서버의 `causeAssessments`는 다섯 원인의 조사 제목, 관측 근거, 부족한 자료와 다음 확인 항목을 제공합니다. 커버리지는 배경 격자와 통화의 RSRP·PHR, 셀 중첩은 같은 주파수에서의 셀 복귀, 셀·주파수 전환은 서빙 식별자의 반복 변경 또는 EARFCN 변경을 조사합니다. A3는 원본 시각에 연결된 보고만 표시합니다. CDR 시작 시간대·종료 셀이 같은 통화와의 비교는 용량을 확정하는 지표가 아닙니다.

모델 입력의 `sourceHypothesisCandidates`와 `sourceInvestigationCandidates`는 현재 전송한 실제 대상·T 근거·동일 분류 SOP의 허용 연결 목록입니다. 통화와 배경 MDT를 섞지 않는 자료 종류별 목록을 제공해 참조 오류를 줄입니다. Qwen은 실제 충족 기준과 부족한 자료에 따라 자체 설명을 작성하고 검증받습니다. 이 목록을 Qwen 결과로 저장하거나 실패 응답을 성공으로 바꾸지 않습니다.

`report.investigations`는 원인 가설과 구분한 1~6개 조사 제안입니다. 각 항목의 `targetIds`와 `evidenceIds`는 실제 Qwen에 전달된 같은 대상의 근거여야 합니다. `title`, `reason`, `nextCheck`는 해당 POT·통화의 관측과 연결된 조사 설명이며, 원인 가설이 없어도 제시할 수 있습니다. 대상별 수치는 선택한 대상의 근거와 다시 대조합니다. 실제 선택한 서로 다른 POT 개수 설명은 허용하지만 이 개수를 SINR 등 측정값으로 바꿀 수 없습니다.

모델 입력이 `targetIdPolicy: evidence-id-alias-v1`을 선언하면 모델은 긴 내부 ID 대신 대상의 실제 T 근거 번호를 `targetIds`에 사용할 수 있습니다. 서버는 현재 전송된 근거가 단 하나의 실제 대상에 정확히 대응할 때만 공개 보고서의 내부 ID로 연결합니다. 알려진 내부 ID는 그대로 유지하며, 철자가 틀린 ID를 추측하거나 다른 근거로 바꾸지 않습니다. 모호한 매핑·미전송 대상·다른 대상의 근거·중복 선택은 거절합니다. 원본 응답을 수정하지 않고 `referenceResolution.targetAliases`에 연결 내역을 남기며 입력·응답 확인 화면에서 펼쳐볼 수 있습니다.

MDT·종료·통화 무선 변화 외에, 대표 상세 통화 중 날짜·Cell 분산과 낮은 저장 QoE를 고려한 최대 6개 `call-quality` 대상에 원본 MOS·저장 QoE·Drop·RSRP/RSRQ/SINR·송수신 RTP 6종을 연결합니다. 후보 구성 전체에서는 날짜·고객에 걸친 Cell·시작 시간대 반복을 최대 3개 `call-pattern` 대상으로 만듭니다. 이 두 종류에는 원인 카테고리와 원인 조치 SOP를 허용하지 않습니다. 반복 관측은 저품질 선별 집단 안의 반복이며 지역 불량률·과부하가 아닙니다. RTP에는 확인되지 않은 %·ms 단위를 붙이지 않습니다.

같은 원본 통화의 `call-radio`와 `call-quality`는 모델 전용 익명 `callRef`를 공유합니다. 한 통화로 결합할 때는 실제 `callIds`와 관측 날짜가 같아야 합니다. 여러 통화를 독립 조사 대상으로 표시할 때는 각 대상이 단 하나의 실제 원본 통화·날짜에 대응해야 하며, 통화별 표현이나 실제 참조로 구분합니다. 각 통화의 무선·음성 대상이 모두 갖춰진 완전한 쌍들도 독립 표시할 수 있습니다. 어느 경우에도 다른 통화를 동일 통화로 주장하거나 통화 간 지표 시각을 결합하는 문장은 거절하며, 제목의 ‘통화별’ 표현만으로 본문의 잘못된 동일 통화 주장을 허용하지 않습니다. 별도 날짜 배경 MDT·다른 종류의 집계는 한 통화 조사에 섞지 않습니다. 원본 종료 코드를 본문에 그대로 반복하는 기존 가설 규칙은 조사 질문에는 강제하지 않지만, 특정 RTP 수신 손실·타임아웃 등을 주장하면 실제 원문에 그 사건이 있는지 검증합니다.

실제 AI가 고른 조사 POT는 지도 표시 수와 선택에 반영하되 원인 가설 수와는 별도로 셉니다. 통화는 같은 저장 사본의 실제 구성 통화 링크로 연결하며 임의의 POT나 가까운 기지국에 붙이지 않습니다. 실패한 재분석이 있어도 이전 성공 결과를 유지하고 최신 실패 코드·설명을 따로 표시합니다. 성공 결과가 없으면 원본의 조사 설명을 **근거 규칙 검토**로 보여주며 Qwen 성공이나 저장 결과로 처리하지 않습니다.

전체 후보 근거를 먼저 **근거 규칙 검토**로 검토합니다. 기본 조사 제안에서는 실제 대상 ID의 겹침을 `조사 대상 겹침 / AI에만 / 규칙에만`으로 비교하며 원인 분류를 추론해 붙이지 않습니다. 원인 가설이 있는 기본·고급 보고서는 같은 원인 분류·같은 대상 기준으로 비교합니다. 이는 별도 언어 모델의 의견이나 인과 검증이 아니라 명시적인 관측 기준에 따른 우선 조사 목록입니다. 커버리지 검토는 서로 다른 POT의 기준 이하 비율·측정 가중치·동일 날짜와 대역의 인접 비교를 함께 제시하며 희소 표본과 통화 시점의 자료 공백을 구분합니다.

RTP timeout, Tx/Rx BYE, 미등록 FC 원문만으로 장비·전송·단말의 책임 구간을 확정하지 않습니다. 실제 종료 유형, 반복 관측, 종료 주체 및 첫 중단 구간을 찾기 위한 SIP·RTP/RTCP 대조를 제시합니다. 배경 MDT는 통화 당시 위치·서빙 Cell과 다릅니다. [RFC 3261 §15](https://www.rfc-editor.org/rfc/rfc3261.html#section-15)의 세션 종료 의미와 [RFC 3550 §6.4.4](https://www.rfc-editor.org/rfc/rfc3550.html#section-6.4.4)의 구간별 수신 보고 비교 범위를 판단의 한계로 참조합니다.

대규모 후보는 전체 POT를 서버에서 검토한 뒤 Qwen에 우선 조사 지점과 분산 비교 지점의 상세 근거를 제한해 보냅니다. 전체 수와 실제 전송 수, 선택 기준을 실행 기록에 명시합니다. 화면과 저장 사본의 상세 대상은 AI에 실제 전송한 대상, 근거 규칙의 우선 대상, 보고서가 연결한 대상의 합집합입니다. 전체 검토 수와 상세 표시 수·생략 수는 `publicCoverage`로 구분하며, 나머지 POT의 상세 분포는 해당 POT를 선택해 조회합니다. 일반 집계와 연결한 근거·SOP·원본 통화 링크는 유지하고, 사용하지 않는 전체 대상 목록과 통화 무선 시계열 원문을 사본에 반복 저장하지 않습니다. 서버의 전체 수집 근거와 검증·근거 규칙 검토는 줄이지 않습니다. 숫자·구조·근거 연결 검증은 유지하며 교정 가능한 Qwen 응답 오류만 한 차례 추가 요청합니다. 교정도 실패하면 실패로 남기고 이전 성공 결과를 보존합니다.

후보 조건별 최근 세 결과의 저장 사본은 합계 64 MiB까지 허용합니다. 새 사본이 이 한도를 넘으면 쓰기 전에 저장 실패를 표시하고 이전의 읽을 수 있는 저장 파일을 그대로 보존합니다.

## 설정과 비식별 처리

기존 `.env`의 Qwen 설정을 사용하며 주소·키·인증 헤더는 서버 밖으로 전달하지 않습니다. 설정 우선순위와 연결 검사는 [기존 고객 분석 문서](qwen-customer-analysis.md)를 따릅니다.

후보 전용 요청 옵션은 `QWEN_CANDIDATE_EXTRA_BODY_JSON`으로 설정합니다. 기본은 `{}`이며 공통 옵션 위에 후보 옵션을 최상위 키 단위로 덮어씁니다. `chat_template_kwargs`는 객체 전체를 교체합니다. 고객·통화 분석의 요청 옵션은 바꾸지 않습니다. 보호 필드와 지원하지 않는 키는 공통 옵션과 같은 검증으로 거부합니다.

```dotenv
# 로컬 SGLang/vLLM의 해당 Qwen chat template이 이 스위치를 지원하는 경우
QWEN_CANDIDATE_EXTRA_BODY_JSON={"chat_template_kwargs":{"enable_thinking":false}}
```

후보 리포트의 최종 JSON 예산이 내부 추론으로 소진될 때 사용할 수 있습니다. 실제 출력 토큰 한도는 기존 `QWEN_MAX_TOKENS`를 그대로 사용합니다. [Qwen3.8-Flash-Next 모델 카드](https://huggingface.co/Qwen/Qwen3.8-Flash-Next)의 해당 서빙 엔진 설정을 확인합니다.

실제 병합된 전송 옵션은 **AI 입력·응답 확인 → 전송 옵션·사본 식별값**에 보관됩니다. 후보 작업의 재사용 키도 같은 유효 옵션을 사용하므로 설정이 바뀐 새 요청은 다른 옵션의 과거 결과를 가져오지 않습니다. 공통값을 바꿨더라도 후보 override로 최종 요청이 동일하면 같은 결과를 재사용할 수 있습니다.

모델에는 집계·자료 충분성·비식별 Cell 별칭과 허용된 SOP만 보냅니다. 고객 ID·계약번호·원본 통화 ID·좌표·원본 상세 덤프·로컬 원본 링크를 보내지 않습니다. 원본 연결은 로컬 근거 자료에만 남깁니다.
