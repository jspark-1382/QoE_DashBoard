## 1. 요청의 의미와 목표

요청은 기존 화면의 수치를 바꾸는 작업보다, 본부장 피드백의 의미를 검토해 개선 방향과 개발 순서를 정하고 **기존 화면과 개선 화면을 비교할 수 있게 설계하는 것**이다.

보고서의 중심 질문은 “단말 위치를 얼마나 정밀하게 계산하는가?”에 그치지 않고 **“어느 지역을 먼저 조사·개선해야 하며, 그 근거를 현장에서 확인할 수 있는가?”**이다. 따라서 데이터의 모집단과 위치 근거를 설명하고, 후보 선정 → 관련 고객·통화 → 현장 확인으로 이어지는 흐름을 우선한다.

사용자가 명시한 화면 제약:

- 현재 `품질 현황`과 `기존안`의 본문·집계·기본 진입 화면을 유지한다.
- 상단 `기존안` 탭 **바로 오른쪽**에 표시명이 정확히 `개선 1안`인 탭을 신설한다.
- `기존안`과 `개선 1안`을 같은 분석 조건으로 오가며 비교할 수 있게 한다.
- 새 안의 실험 결과가 기존 화면의 데이터·판정·지도에 섞이지 않도록 한다.

## 5. 같은 조건으로 비교하는 방식

### 5.1 비교할 항목

비교에는 두 층이 있다.

1. **화면 비교:** 기존안 탭과 개선 1안을 같은 출처·기간·일별 시간창·MOS 조건으로 전환한다. 원본 CDR 총수·유효 MOS·저MOS 수는 같은 집계 조건에서 일치해야 한다. 시간대/hour와 단일 고객은 상세 탐색 조건이며 상단 전체 집계의 분모를 바꾸지 않는다.
2. **후보 산정 비교:** 개선 1안 내부의 `현행 후보 산정 방식 / 개선 방식` 비교표에서 지역 후보·Cell 참고 후보·제외 사유·순위 변화를 비교한다. 기존안 화면에 원래 없던 후보 수를 기존안의 원래 기능인 것처럼 설명하지 않는다.

후보 수 감소 자체를 개선 성공으로 보지 않는다. BYE 제외, 위치 검토, 모집단 변화 등 변경 이유와 남은 조사 근거를 설명한다.

### 5.2 공통 조건 계약

조건은 두 종류로 나눈다. **집계 조건**은 `source`, `sourceRevision`, `dateStart`, `dateEnd`, 일별 시간창 `from/to`, 원본 MOS 기준이다. **전달 가능한 상세 탐색 조건**은 `hour`와 단일 고객 선택이다. 날짜는 KST 시작일 기준, 시간창은 선택한 **각 날짜**에 적용한다. 자정을 넘는 시간창은 자동 해석하지 않고 두 날짜·시간 범위를 다시 선택하게 한다.

- URL은 기존 `dateStart/dateEnd/date/from/to/hour/metric/customer` 명칭과 호환한다. `date`는 상세 이동을 위한 기준일이고 기간을 대신하지 않는다.
- 기간 없는 신규 경로 직접 진입은 manifest의 전체 가용 기간을 기본으로 한다(현재 5일). `date`만 명시한 링크는 해당 하루로, `dateStart/dateEnd`가 있으면 그 기간으로 해석한다. 모드를 생략하면 3일 이상은 holdout, 1~2일은 screening으로 초기화하고 화면에 모드를 표시한다.
- 기존안의 상단 집계가 hour/고객 선택으로 좁혀지지 않는 현재 의미를 유지한다. 새 안도 상단 퍼널·후보 산정은 집계 조건만 적용하고, hour/고객은 상세 목록·선택 관측점 탐색에만 적용한다. 고객별 집계는 상단 전체와 별도 패널이다.
- 비교 revision은 신규 URL 매개변수 `compareRevision`으로 전달한다. 기존안 셸의 이동용 어댑터에서 읽기·정규화·뒤로가기 때 이를 보존하고 로드한 manifest revision과 대조한다. 기존 `parseSelection`이 revision을 보존해 준다고 가정하지 않는다. 불일치 시 비교 안내를 표시하고 동일 조건 판정을 차단하되 기존 본문의 계산은 변경하지 않는다.
- 기존안 셸에서 현재 선택과 필터로 `improvementHref`를 만든다. 새 안에서는 같은 조건의 `legacyHref`를 만든다. 새 안의 링크에는 `metric=mos`를 명시한다.
- 새로고침, 브라우저 뒤로/앞으로, 직접 URL 진입에서도 같은 조건을 복원한다.
- 기존안이 QoE 지표이거나 실측 출처인 경우, 새 안은 `MOS·MDT 조건으로 비교 가능` 안내와 명시적 조건 전환을 제공한다. 사용자의 조건을 조용히 바꾸지 않는다.
- 행정동·후보·위치 종류·표 페이지 등 서로 대응하지 않는 탐색 조건은 각 화면의 조건으로 구분한다. 비교용 상단 CDR 집계를 이 조건으로 몰래 좁히지 않는다.
- 복수 고객 선택은 새 안의 후보 상세용이다. 단일 고객만 지원하는 기존안과 복수 고객 조건을 동일하다고 표시하지 않는다.
- 누락된 날짜, 중복 통화 ID, 원본 revision 불일치가 있으면 비교를 차단한다. 정상적으로 0건인 결과와 자료가 없는 상태를 구분한다.

기존 `품질 현황`은 내부 상태 전체를 URL로 제공하지 않는다. 본 단계에서 이 본문을 수정하지 않으며 **그 화면에서 새 탭을 열 때 전체 필터가 자동 복제된다고 보장하지 않는다**. 새 탭 진입 후 공통 조건을 표시하고, 동일 조건 보장은 `기존안 ↔ 개선 1안` 사이에 적용한다.

## 6. 개선 1안 화면 구성

```text
[공통 상단 탭 ... 기존안 | 개선 1안]
[기간·일별 시간·MOS·원본 버전·비교 조건] [같은 조건의 기존안 보기]
[전체 CDR → 유효 MOS → MDT 연결 → 위치 활용 가능] [저MOS만 보기]
[지역 후보 지도: GNSS/검토 통과 추정/주변 도트] [조사 순위·선정 근거]
[선택 후보: 고객 수·통화 수·관측일·재관측·위치 불확실성]
[고객 A/B/C | 선택 기간 전체 통화 | MOS·위치 근거·Drop·원본 상세]
[현행 후보 산정 방식과 비교] [현장 검증 자료와 확인 상태]
```

상단은 “얼마나 분석할 수 있는가”, 중앙은 “어디를 조사할 것인가”, 하단은 “어떤 통화에서 무엇을 확인할 것인가”를 설명한다. 규칙·파라미터·상세 경고는 펼쳐 보기로 제공하되, 위치 종류와 분석 가능 건수는 항상 보인다.

지도는 GNSS 실측과 검토 통과 추정을 색·모양·범례로 구분한다. 관련 저MOS 통화의 관측 도트를 켤 수 있게 하고, 대표 위치와 여러 원본 관측점의 개수를 구분한다. 통화 수는 관측점 수에 따라 증가하지 않는다. BYE 기지국 참고점은 지역 후보 기본 지도에서 제외하고 고객 상세에서 별도 아이콘으로 표시한다.

주변 저MOS 도트는 발견/검증기간 전체에서 채택된 대표점 중 발견 구성점과 eps 이내인 모든 통화를 대상으로 한다. 후보 구성원, 검증 신규 고객, 검증 기존 고객을 구분하며 대표 통화 몇 건만으로 대체하지 않는다. 같은 통화의 전체 GNSS 이동 관측은 별도 `원본 경로` 레이어에 표시하고 후보 주변 점과 구분한다.

`MOS 저하 위치 확정`, `불량 원인 확정`, `AI 분석` 같은 표현을 사용하지 않는다. 기본 설명은 `저MOS 통화와 연결된 관측·추정 위치`, `규칙 기반 조사 후보`, `현장 확인 필요`다.

## 7. 위치 입력과 3-Site 채택 정책

통화당 후보 산정용 대표 위치는 최대 1개다. 원본 위치·MOS를 수정하지 않고 별도 레코드에 채택·제외 이유를 기록한다.

1. 현재 원본 정책을 만족하는 동일 통화의 GNSS 관측을 우선한다. 실제 관측시각, CDR 종료시각과의 차이, `direct-gnss/last-known-gnss`를 보존한다. 기존안 대비 입력 확대 효과를 확인하는 1차 비교에서는 GNSS 시점 정책을 동시에 변경하지 않는다.
2. GNSS가 없을 때, 원본 근거로 `strict-3-site-v1` 검토를 **재현하여 통과**한 추정을 사용한다. `usedSiteCount >= 3` 또는 `evidence=estimated`만으로 채택하지 않는다.
3. `three-site-rough`, 2-Site, 사이트 무게중심, 검토 미통과/근거 누락 추정은 지역 후보 입력에서 제외한다. 필요하면 기본 OFF인 `추가 위치 검토` 레이어에서 별도 표시한다.
4. BYE Cell 단독 기지국 좌표는 지역 후보 입력에서 제외하고 고객 상세의 기지국 참고 근거로 보존한다.
5. 시각·연결 통화·revision·좌표 근거를 검증할 수 없으면 제외 사유를 집계한다. 다른 통화의 GNSS나 Cell 위치로 채우지 않는다.

검토 기준은 `lib/location-estimation/review.ts`의 현행 값을 재사용한다: 독립 사이트 3개 이상, 모델 불확실성 1,500m 이하, 잔차 800m 이하, geometry 0.10 이상, 사이트 관측 시간차 최대 10초, 관측 창 30초 이하, 모델 점수 40 이상, 거리 포화 비율 0.5 이하, 비현실적 이동 없음 및 검증된 기지국 출처. 이 수치는 실제 위치 정확도 보증이나 통계적 신뢰구간이 아니다.

`normalizeDay`가 적용하는 최근 GNSS 이동 가능 범위 검사까지 통과한 근거를 사용한다. 기존 Python overview 생성기의 더 느슨한 별도 판정은 새 안의 검토 통과 증명으로 쓰지 않는다. 기존 Python 정책 자체는 이 작업에서 변경하지 않는다.

현재 엄격 검토 통과 위치가 0건인 상태에서는 `검토 통과 3-Site 0건`으로 보여준다. 후보를 늘리려고 판정 문턱을 낮추지 않는다. GNSS 확보와 radio 근거 확보는 중복 가능하므로 원시 확보량과 대표 위치 채택량을 별도 기록한다.

## 8. 후보 선정·범위·순위

### 8.1 기본안과 발견/검증 구분

아래는 보고서에서 확정된 사양이 아니라 **현행을 출발점으로 정한 개발 기본안**이다.

- 저MOS: 유효한 원본 MOS(v5) `1 <= MOS < 3`. 결측·범위 밖 값 제외.
- DBSCAN: haversine, `epsM=100`, `minSamples=2`. 한 통화의 여러 관측점으로 밀도를 부풀리지 않는다.
- 지역 후보 기본 문턱: 고유 저MOS 고객 `>=3`, 저MOS가 관측된 서로 다른 날짜 `>=2`.
- 발견/검증 모드: 기본 5일은 앞 4일로 발견하고 마지막 1일에서 발견 고객을 제외한 신규 고객 `>=2`의 저MOS 재관측을 확인한다. 검증일 데이터를 중심·범위·순위 계산에 미리 넣지 않는다.
- 기간 일반화: `holdout`은 연속된 최소 3일이 필요하며 마지막 하루를 검증일로 둔다. 1~2일 선택에서는 `screening` 탐색 모드를 명시적으로 제공한다. 발견일 2일 문턱은 유지하므로 하루 자료는 점/관측 그룹만 표시하고 반복 지역 후보로 승격하지 않는다.
- 재관측을 만족하지 못한 후보도 `발견 후보·재관측 미충족`으로 볼 수 있다. 현장 확인 완료와 통계적 독립 검증으로 과장하지 않는다. 같은 고객을 배제하더라도 같은 Cell·공간 환경이 남는 한계를 설명한다.

비교 시 현행 방식과 개선 방식의 기간·시간·고객 모집단·모드·파라미터를 일치시킨다. 현행 고정 파일을 필터링한 결과를 임의 기간 재산정 결과라고 제시하지 않는다. 현행 호환 산정은 별도 출력에서 재현하고 기존 빌더를 바꾸지 않는다.

공간 후보의 신규 고객 집합은 `검증일 해당 후보 100m 이웃 내 저MOS 고객 - 해당 후보 발견기간 저MOS 구성 통화 고객`이다. 전체 네트워크에서 처음 등장한 고객이라는 뜻은 아니다. 검증일의 기존 고객 재발도 주변 통화 목록에는 포함하되 신규 고객 수에서는 제외한다.

검증점과 후보의 연결은 **발견기간 구성점 중 어느 하나와 거리가 epsM 이하**인 경우다. 중심점 또는 표시 원 안에 있다는 이유만으로 연결하지 않는다. 한 검증 통화가 여러 후보의 이웃이면 각 후보의 재관측 근거가 될 수 있으나 후보별 한 번만 세고, 전체 재관측 통화/고객 수는 집합의 합집합으로 중복 제거한다. 이 한계는 인접 후보 안내에 남긴다.

직접 비교 대상은 **GNSS 공간 후보 방식과 GNSS + 엄격 검토 통과 추정 공간 후보 방식**이다. 기존 종료 Cell 후보는 별도 참고표에 두며 같은 지역 후보 순위에 합산하지 않는다. 과거 게시 후보 5개(공간 3·Cell 2)는 그 원본 revision과 고정 5일 조건에 한해 `게시 기준선`으로 표시한다. 임의 기간의 Cell 후보 재산정은 이번 단기 범위에 포함하지 않는다.

### 8.2 병합·분리와 과대 선정

- DBSCAN은 가까운 점의 사슬로 100m를 넘는 군집을 만들 수 있다. `100m`를 후보 전체 반경이라고 설명하지 않는다.
- 후보별 실제 구성 통화·고객·일자, medoid, 최대 중심거리, 최대 두 점 거리, 표시 범위를 저장한다. 표시는 포괄 범위이며 위치 정확도 반경이 아니다.
- 1차 구현에서는 추가 자동 병합/분리를 하지 않는다. 인접 후보는 관련 후보로만 연결한다.
- 개발 제안 기준으로 최대 두 점 거리 `> 2 × epsM`이면 `범위 검토 필요`로 표시하고 기본 조사 순위와 분리한다. 후보를 삭제하거나 임의로 쪼개지 않으며, 이 기준은 현장 검증 후 조정한다.
- 50/100/200/300/500m의 민감도를 같은 자료에서 확인한다. 강원도 실제 자료가 없으면 `외곽 실데이터 검증 미실시`로 기록하고, 합성 희소·사슬·단독점 테스트만으로 실검증 완료를 주장하지 않는다.

### 8.3 설명 가능한 조사 순위

확정 투자 우선순위가 아닌 `조사 순위`를 사용한다. 범위 검토 후보를 분리한 뒤 발견기간의 **고유 저MOS 고객 수 내림차순 → 저MOS 관측일 수 내림차순 → 저MOS 통화 수 내림차순 → GNSS 채택 통화 수 내림차순 → 안정적인 후보 ID**로 정렬한다. 별도 근거 없는 가중 점수는 만들지 않는다. 재관측 상태는 별도 배지·필터로 제공한다.

신규·유지·제외·분할/병합 가능성 비교는 후보 ID 일치가 아니라 구성 통화 집합과 공간 범위를 근거로 한다. 통화 겹침 관계를 모두 기록하고, 겹침이 없으면 대응 없음으로 남긴다. 가까운 중심점 하나에 강제로 일대일 매칭하지 않는다.

## 10. 수집·활용 가능 건수와 분모

상단 기준 모집단은 동일 출처·revision·기간·시간의 전체 CDR이다. 원본이 특정 지역 수집 자료이면 `원본 수집대상 지역`으로 표기하며, 좌표가 있는 일부 통화만으로 전체 지역 모집단을 다시 정의하지 않는다. 고객 상세와 후보 선택은 별도 부분집합이다.

- `N`: 전체 고유 CDR 통화.
- `M`: N 중 MOS 1~5인 통화. 미평가/범위 밖은 제외 사유를 분리한다.
- `D`: M 중 동일 통화에 MDT가 유일하게 연결된 통화. 복수 후보 연결은 별도 건수다.
- `G`: D 중 대표 GNSS 채택 통화.
- `T`: D 중 GNSS가 없고 엄격 3-Site 검토를 통과해 대표 위치가 채택된 통화.
- `U = G ∪ T`: 새 안에서 지역 분석에 활용 가능한 통화. G와 T는 대표 위치 선택으로 서로 배타적이다.

`N → M → D` 다음에 **GNSS / 검토 통과 3-Site로 분기하고 U로 합친다**. GNSS 다음에 3-Site를 필수 순서로 요구하는 직렬 퍼널로 그리지 않는다. 원시 GNSS/3-Site 보유량은 중복 가능하므로 이 채택량과 별도 표시한다.

각 카드에는 `건수 / 전체 N 대비 비율`을 기본으로 표시하고, 전 단계 대비 비율은 분모 이름과 함께 보조로 표시한다. 분모 0은 `산출 불가`다. 저MOS만 보는 모드에서는 `Npoor`, `Dpoor`, `Gpoor`, `Tpoor`, `Upoor`를 따로 계산하고 `Npoor/N`, `Npoor/M`, `Upoor/Npoor`를 구분한다.

현재 overview만으로 MDT 유일 연결 여부를 증명할 수 없으면 원본 연결 근거에서 새 집계를 만든다. `hasMdt`, 관측 행수, 고객-일자 파티션 존재를 동일 통화 유일 연결로 대신하지 않는다. 행정동/후보 도트 클릭으로 상단 전체 분모를 바꾸지 않는다. 저MOS 중심 MDT 부분표본으로 행정동 전체 불량률을 계산하지 않는다.

## 11. 고객·통화와 현장 확인

후보를 선택하면 관련 고객을 후보 안에서 고정된 A/B/C 별칭으로 구분한다. 관련 통화뿐 아니라 그 고객의 **선택 기간 전체 CDR 통화**를 한 목록으로 확인한다. 후보 연관 통화는 별도 배지로 표시한다. 그 고객이 선택 기간에 다른 지역에서 한 통화를 후보 지역 통화로 편입하지 않는다.

목록은 날짜·시각·원본 MOS·GNSS/추정/기지국/미확인·SIP 11.REASON 기반 Drop 여부를 제공한다. SIP 상태코드나 미확인 종료값으로 절단을 확정하지 않는다. 상세 링크는 그 통화의 실제 고객 ID·raw call ID·날짜를 사용한다. 기존 고객 분석 페이지의 내용은 변경하지 않는다.

현장 자료는 후보 ID, 측정시각, 실제 관측 위치, 녹음 참조, 측정 MOS, RF 참조, 확인 결과를 연결하는 별도 구조로 둔다. 자료가 없으면 `현장 자료 미확보`로 표시한다. 초기 범위는 제공된 자료의 조회·재생이며, 업로드 서비스·외부 발송은 포함하지 않는다. 실제 녹음과 해당 측정 MOS가 확보되기 전에는 다른 통화의 음성을 예시로 연결하지 않는다.

SCAN은 같은 지역·기간·모집단·정의가 확인된 경우에만 후보 대응/미검출 사례를 비교한다. 자료가 없거나 모집단이 다르면 `비교 조건 미충족`으로 남긴다. 현장 정답이 없는데 정확도·재현율을 만들어 보고하지 않는다.

## 12. 구현 경계와 산출물 계약

새 안의 분석과 출력은 `lib/analyst/voice-improvement-1/`, `components/analyst/voice-improvement-1/`, `public/voice-improvement-1/`로 분리한다. 기존 타입을 확장하기 위해 원본을 재작성하지 않고 새 안 전용 어댑터를 사용한다. 기존 로더·시간·MOS 검증 함수는 읽기 전용으로 재사용한다.

신규 산출물은 `schemaVersion=voice-improvement-1-v1`, 원본 revision, 실제 입력 파일 해시, 기지국 인벤토리 해시, 분석 조건, 정책·알고리즘 버전, 발견/검증 날짜, 제외 사유별 통화 수를 포함한다. 출력 경로는 `public/voice-improvement-1/<revision>/<scopeKey>/report.json`이며 `scopeKey`는 정규화한 집계 조건·모드·파라미터의 SHA-256 앞 20자리다. 키 정렬·배열 순서를 명시한 직렬화를 사용한다. hour/고객/후보 선택은 탐색 조건이므로 이 키와 배치 후보 입력에서 제외한다. 날짜·일별 시간창·모드가 다르면 서로 다른 결과다.

후보 수·날짜·지역을 검증기에 고정하지 않는다. 0개·여러 개 결과와 위치 미확인도 정상 처리한다. 조건별 산출물이 없으면 `현재 조건의 후보 산출물 없음`으로 표시한다. 5일 결과를 다른 기간의 결과처럼 보여주지 않는다. 초기 구현은 로컬 배치 재산정이며 브라우저에서 무거운 MDT 전체 연산을 수행하지 않는다.

## 13. 개발 단계와 완료 기준

| 단계 | 할 일 | 완료 증거 |
| --- | --- | --- |
| 1. 비교 기준 고정 | 원본·기존 소스 해시, 공통 기간/시간 조건, 현행 후보 재현 조건 기록 | 같은 조건 CDR·MOS 합계 일치, 기존 소스·데이터 불변 |
| 2. 후보와 지표 분리 | 위치 근거 채택·제외, 버전 있는 산출물, 용어/분모 계산 | 지역 입력의 BYE 단독 위치 0건, 미통과 3-Site 제외, 고유 통화 합계 검증 |
| 3. 새 탭 구현 | 개선 1안 경로·메뉴·퍼널·지도·선정 근거·기간 고객 목록 | 정확한 탭 인접, 새로고침/뒤로가기 비교 조건 유지 |
| 4. 비교·검증 | 전후 후보 대응, 반경 민감도, 누락/희소/사슬 테스트 | 변경 이유·미확인 범위 설명, 검증일 누출 없음 |
| 5. 보고 사례 준비 | 제공된 현장 자료와 동일 조건 SCAN 사례 연결 | 자료 확보 상태와 관측 사실/가설 구분 |
| 6. 투자 검토 | 구간 MOS·위치 데이터·NQI/WING 범위와 부하 검토 | 데이터 요건·추가 확보량·성능 실측·기간/비용 추정 근거 |

단기 개발 공수는 기존 로컬 환경과 자료 재사용을 전제로 **개발자 1명 약 8~12 작업일의 계획용 추정**이다. 현장 자료·강원도/SCAN 자료·외부 시스템 협의 대기는 제외한다. 공식 일정·담당자·예산으로 간주하지 않는다.

중장기에는 RTP/RTCP 원본의 실제 시계열·방향·코덱·시간 기준을 먼저 확인한다. 통화 MOS 하나를 10/30초마다 복사해 구간 MOS로 만들지 않는다. 대표 하루 자료로 처리량·메모리·저장 바이트를 실측하고, `sum(ceil(통화길이/구간초)) × 구간별 저장량 × 보관일 × 복제계수`로 저장량을 산정한다. 현재 MDT MOS가 변하는 시간 구간을 제공하는지도 검증해야 한다.

## 14. 인수 기준

- 기존안 바로 오른쪽에 `개선 1안`이 한 번 나타나며 모든 공통 메뉴에서 활성 표시가 정확하다.
- 기본 `/` 진입과 기존안의 본문·스타일·기존 데이터·집계는 유지된다.
- 기존안과 개선 1안은 같은 공통 조건의 CDR/유효 MOS/저MOS 총수가 같다. 지원하지 않는 조건은 비교 가능하다고 표시하지 않는다.
- BYE 단독 좌표와 미검토 거친 3-Site 위치는 새 지역 후보 입력에 포함되지 않는다. 상세에서 기지국 근거는 조회 가능하다.
- DBSCAN 이웃거리, 후보 표시 범위, 위치 불확실성의 의미가 구분된다.
- 고유 고객·통화·관측일·연속 통화·연속 관측일이 별도이고, 5명과 5일을 혼동하지 않는다.
- 전체 CDR·저MOS·선택 고객·지도 부분표본의 분모를 섞지 않는다. G와 T의 중복 채택은 없다.
- 선택 기간과 산출물 조건/revision이 다르면 표시를 차단한다. 0건·자료 없음·채택 불가를 구분한다.
- 현장/외곽/SCAN 검증 자료가 없는 상태를 완료로 표시하지 않는다. 통화 MOS로 열화 순간이나 원인을 확정하지 않는다.

세부 개발 작업·파일·검증은 [개발 계획](../plans/2026-11-07-voice-experience-improvement-1.md)에 둔다.

## 15. 독립 검토 반영

설계 검토에서 확인한 세 가지 중요한 판단을 반영했다: (1) hour/고객은 상단 분모와 분리된 탐색 조건이며 기존안의 계산을 유지한다. (2) 신규 검증 고객은 후보별 발견기간 저MOS 구성 고객과의 차집합이다. (3) 검증점은 발견 구성점과의 eps 이웃으로 연결하며 여러 후보에서 중복될 때 전체 합계는 합집합으로 계산한다. 모두 현 코드와 요청 범위에서 결정할 수 있어 추가 사용자 입력 없이 설계에 명시했다.
