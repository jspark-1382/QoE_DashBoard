# QoE 분석가 화면 개편 계획

검토일: 2026-10-24 · 기준 코드: main `114831d` · 상태: 1차 개편 구현·검증 완료 (`codex/analyst-workspace`)

## 1. 목표와 판단 기준

사용자가 지정한 주 사용자는 **분석가**다. 분석가가 문제 통화·지역을 찾고, 원본 서비스계약번호로 대조하며, 특정 시점의 무선값과 위치 근거를 확인하는 작업에 맞춰 화면을 다시 구성한다.

추천 방향은 절제된 분석 작업 화면이다. 큰 표어·장식 카드·상태 배지보다 검색, 통화 목록, 지도, 시간축, 관측 근거에 공간을 배분한다. 밝은 무채색 화면은 제안자의 선택이며 사용자가 지정한 색상은 아니다. 다크 모드 확대는 첫 개편 이후로 둔다.

이 문서는 코드 검토에 기반한 개편 계획과 구현 결과를 함께 보관한다. 10절의 시안에 표시된 계약번호·관측값·지도는 설명용 예시다. 실제 구현·검증 범위는 11절에 기록한다.

### 선행 조건: 현재 데이터와 프런트엔드 계약

현재 로컬 `public/mdt-data.json`은 `mdt-v2`, `partitioned: true`이며 고객 10,250명과 고객·일자별 `dataPath`를 제공한다. 목록의 `samples`는 비어 있다. 반면 새로 받은 메인 화면은 `day.samples`를 직접 읽고 상세 파일을 요청하지 않는다. 따라서 실제 데이터가 있어도 빈 화면으로 보일 수 있다. 이것을 단순한 UI 문제로 덮지 않는다.

개편 첫 단계에서 inline/partitioned 입력을 한 로더로 수용하고, 상세 로딩·오류·재시도·이전 요청 취소를 정의한다. 전체 현황은 10,250개 상세를 처음부터 다운로드하는 방식으로 만들지 않는다. 일자별 집계 자료를 준비하고, 계약을 선택할 때 상세를 읽는다. 이 단계에서 원본 계약번호 문자열과 독립 통화 목록·결측 의미도 함께 보존한다.

## 3. 화면 역할

상단 메뉴는 두 개로 구성한다. 긴 플랫폼 소개와 `EXECUTIVE DASHBOARD` 표시는 짧은 제품명 **QoE 분석**으로 바꾼다.

| 화면 | 분석가의 질문 | 핵심 구성 |
|---|---|---|
| 품질 현황 | 어느 지역·시간·통화를 먼저 조사할까? | 분석 범위, 일자별 요약, 품질 지도, 영향 계약·통화 순위 |
| 계약·통화 분석 | 이 계약의 어떤 통화·시점에 무엇이 관측됐나? | 원본 계약 검색, 통화 목록, 지도·시간축, 선택 관측 근거 |

고급 분석은 세 번째 대형 메뉴로 늘리지 않는다. 계약·통화 분석의 **분석 설정**에서 알고리즘 비교, 거리모델, 시간창, RSRP 집계 방식을 연다.

## 4. 분석 흐름과 선택 규칙

1. 일자·데이터 출처를 선택하거나 원본 서비스계약번호를 검색한다.
2. 전체 지도 영역을 선택하면 그 영역에 포함되는 통화 목록을 먼저 보여준다. 임의의 최악 통화 소유자로 바로 이동하지 않는다.
3. 계약·통화 분석에서 통화 하나를 선택하면 지도와 무선 차트가 같은 통화 범위로 바뀐다.
4. 지도 점, 차트 커서, 이전·다음 관측으로 시점을 선택하면 우측 원본값이 함께 바뀐다.
5. 시점을 움직여도 통화의 전체 표시 범위는 유지한다. 범위 변경은 명시적인 통화·기간 선택으로만 수행한다.
6. 상단 경로에 `품질 현황 / 계약번호 / 통화 시간`을 표시하고 이전 조사 범위로 돌아갈 수 있게 한다.

선택 상태는 `view / source / date / customerId / callId / sampleId`를 중심으로 정리한다. 레이어 표시와 알고리즘 설정은 분석 대상 선택과 분리한다. URL에 계약 내부 ID·일자·통화 선택을 복원할 수 있게 하되 원본 서비스계약번호를 URL 키로 바꾸지 않는다.

## 5. 대표 시안: 계약·통화 분석

### 상단

- 서비스 계약번호 검색을 가장 먼저 배치한다. 정확 일치·부분 검색·선행 0 보존·복사를 지원한다.
- 검색어를 입력하는 동작과 계약을 선택하는 동작을 구분한다. 검색 결과는 제한하거나 가상화하고 선택된 계약은 목록 밖으로 사라지지 않게 한다.
- 일자와 데이터 출처를 같은 줄에 둔다. 고정 `Voice`는 선택상자가 아닌 출처 정보로 표시한다.
- 요약은 작은 한 줄로 배치한다: **통화 수 / 평가 가능 통화 수 / 저품질 통화 수와 분모 / GNSS 확보율**.
- GNSS 확보율은 통화 중 유효 관측 이벤트 중 GNSS가 있는 이벤트 비율로 정의하고 분자·분모를 툴팁에서 확인하게 한다. 데이터 형식에 따라 확보율을 계산할 수 없다면 미제공으로 표시한다.

### 본문: 통화 목록 → 지도·시간축 → 관측 근거

- **왼쪽 약 24%:** 통화 시작, 통화 시간, QoE, 평가 상태. 기본 시각순이며 저품질순 정렬·저품질 필터를 제공한다. 선택은 옅은 파랑과 왼쪽 선으로 표시한다.
- **가운데 약 53%:** 선택 통화 지도, 아래에 동기화된 무선 차트. 지도와 차트가 같은 대상·시간을 표시한다.
- **오른쪽 약 23%:** 선택 시각, 위치 출처, 원본 무선값, Cell/기지국, 종료 코드, 관측 근거. 알고리즘 설명보다 원본값을 우선한다.
- 기존 지도 확대용 통화 카드 목록과 본문 통화 표의 중복을 없애 하나의 선택 목록을 사용한다.
- 1366px에서는 오른쪽 근거 패널을 접고 필요할 때 펼친다. 본문 글자를 줄여 세 열을 억지로 유지하지 않는다. 1920px에서는 세 열을 함께 보여준다.

### 지도

- GNSS 관측은 원, 추정 위치는 마름모, 기지국은 삼각형과 명시적 라벨로 구분한다.
- 색상은 사용자가 고른 품질 지표에만 일관되게 대응시킨다. 선택 상태는 파랑 고리·선, 위치 출처는 모양·문구로 구분한다.
- 위치 출처는 `GNSS 관측 / 보간 / 무선 추정 / 위치 근거 없음`으로 설명한다. 실제 지원되는 출처만 표시하며 새로운 보간 계산을 UI 변경에 섞어 추가하지 않는다.
- 기지국 레이어와 무선 추정 영역은 필요할 때 켠다. 서로 다른 위치 출처의 점을 무조건 실측 이동 경로로 잇지 않는다.
- GNSS 좌표계는 확인된 EPSG:5179로 표시한다. GNSS 측정 정확도가 없으면 `정확도 정보 없음`으로 표시한다.
- 추정 신뢰도는 위치 정확도 백분율로 설명하지 않는다. 단일 기지국 좌표를 고객의 실제 좌표로 보여주지 않는다.

### 차트와 근거

- 일간 요약은 **통화별 QoE**를 보여준다. 한 통화의 QoE를 시간에 따라 연속 변화하는 값처럼 그리지 않는다.
- 통화를 선택하면 RSRP(dBm), RSRQ(dB), SINR(dB)을 별도 축의 짧은 차트로 표시하고 시점 커서를 공유한다. 누락 구간과 통화 경계를 넘겨 선을 잇지 않는다.
- MDT에 원본 MOS가 없다면 MOS 열·범례·빈 그래프를 숨긴다.
- `주요 원인` 대신 관측 조건별 건수와 분모를 보여준다. 예: `RSRP −105 dBm 미만 18/42건`. 여러 조건의 동시 발생을 주장할 때는 같은 이벤트에서 충족한 건수만 사용한다.
- `조치 상태`는 실제 담당자·기록·상태 변경 기능을 갖추기 전에는 표시하지 않는다. 근거 없는 정상·모니터링 판정도 만들지 않는다.

## 6. 품질 현황

- 일자·데이터 출처·필터 범위를 명시하고 평가 가능 통화, 저품질 통화, 영향 계약, 위치 확보 현황을 구분한다.
- 평균을 제공한다면 전체 평가 통화를 분모로 계산하고, 저품질 필터 결과의 평균은 별도 이름을 사용한다.
- 순위는 표본 건수만으로 정하지 않는다. 영향 계약 수, 저품질 통화 수, 평가 가능 통화 대비 비율을 각각 제공한다.
- 지도와 순위는 같은 공간 격자와 기준을 사용한다. PCI만으로 서로 다른 기지국·Cell을 합치지 않는다. 위치가 없는 통화도 전체 분모에서 조용히 빠지지 않게 별도 집계한다.
- 클러스터 순위와 통화 목록은 서로 다른 레이아웃 영역을 사용해 같은 격자 셀에 겹치지 않게 한다.

공간 집계의 초기 규칙은 다음과 같이 제안자가 정한다. 지도와 순위는 같은 **60m 격자**를 사용한다. 동일 이벤트에는 GNSS 관측 → 실제로 지원되는 보간 → 무선 추정 좌표 순으로 하나의 위치만 선택하며, 기지국 좌표 자체는 고객 위치로 귀속하지 않는다. 통화 중 유효 위치가 관측된 격자에 해당 통화를 포함하고, 같은 통화가 같은 격자에서 반복 관측되어도 한 번만 센다. 격자의 저품질 비율은 `해당 격자 저품질 통화 수 / 해당 격자 평가 가능 통화 수`다. 같은 통화가 여러 격자에 나타날 수 있으므로 격자별 합계가 전체 통화 총수와 같다고 표시하지 않는다. 전체 숫자는 통화 ID·계약 ID로 다시 중복 제거하고, 화면에 `여러 격자에 걸친 통화는 격자별 중복 포함`을 설명한다. 평가 불가와 위치 없음은 별도로 집계한다.

### 6.1 품질 현황 페이지의 배치

사용자 후속 질문에 따라 품질 현황도 별도의 대표 시안으로 제공한다. 이 페이지는 조사할 대상을 찾는 입구이고, 계약·통화 분석은 선택 대상을 검증하는 작업 화면이다.

| 위치 | 구성 | 분석가가 할 일 |
|---|---|---|
| 상단 | 일자·시간 범위·출처·지역, 원본 계약번호 바로 찾기 | 분석할 모집단을 정하거나 특정 계약으로 바로 이동 |
| 요약 한 줄 | 분석 계약 / 평가 가능 통화와 전체 통화 / 저품질 통화와 비율 / 영향 계약 | 문제 규모를 분모와 함께 확인 |
| 중앙 왼쪽 | 60m 격자의 지역별 품질 지도 | 조사 구역 선택. 지도 이동 자체는 분석 모집단을 바꾸지 않음 |
| 중앙 오른쪽 | 지도와 같은 격자의 조사 구역 순위 | 저품질 통화 수·비율·영향 계약으로 비교. 별도 격자 크기나 표본 건수 가중 순위를 섞지 않음 |
| 중간 | 시간대별 저품질 통화 막대그래프 | 통화 시작 시각 기준으로 집중 시간을 선택 |
| 하단 | 선택 구역의 원본 계약번호·통화 시각·QoE·위치 출처·분석 링크 | 조사할 통화를 확인하고 계약·통화 분석으로 이동 |

지도는 원 크기를 저품질 통화 수, 색상을 저품질 통화 비율에 대응시키고 범례를 제공한다. 표시할 지리 정보가 없으면 임의 지역명을 만들지 않고 기지국 ID·격자 ID로 대체한다. 지도와 순위에서 영역을 고르는 것만으로 특정 계약으로 바로 이동하지 않는다.

### 6.2 전체 범위와 조사 범위

- 상단 일자·시간 범위·출처·지역은 전체 분석 범위를 정하며, 이를 바꾸면 전체 요약을 다시 계산한다.
- 지도 이동은 위치 탐색 동작으로 유지한다. 구역 선택은 하단 목록에만 공간 범위를 적용하고 선택 구역명·해제 동작을 표시한다.
- 시간 차트의 막대 선택은 별도의 조사 시간 조건이다. 지도·순위·목록을 함께 좁히고 조건과 해제 동작을 보여준다. 상단 요약은 `전체 분석 범위 기준`으로 유지하며 조사 조건의 수치는 지도·목록에 별도로 표시한다. 차트 자체는 전체 시간 분포와 선택 표시를 유지한다.
- 평가 불가 통화는 평가 분모에 넣지 않되 수를 숨기지 않는다. 위치 없는 저품질 통화는 지도 주변의 별도 조회 링크로 제공하고 공간 선택 목록에 임의로 귀속하지 않는다.
- 통화 행의 `분석`은 원본 계약·일자·통화를 선택한 상세 화면으로 이동한다. 뒤로 돌아오면 이전 지도 영역·선택 구역·시간 조건·목록 정렬을 복원한다.

### 6.3 시안의 예시 수치

예시 전체 통화는 3,420건이며 평가 가능 3,180건과 평가 불가 240건으로 나뉜다. 저품질 286건의 비율은 평가 가능 통화 대비 9.0%다. 분석 계약은 1,240개, 영향 계약은 194개다. 위치 없는 저품질 34통화를 제외한 252통화에 지도상 위치가 있다. 이 값들은 실제 원본 재집계 결과가 아닌 화면 설명용 예시다.

시안에서 선택된 구역은 평가 가능 80통화, 저품질 24통화(30.0%), 영향 계약 18개로 표시한다. 하단 목록은 이 구역의 저품질 24통화만 보여준다. 시간 차트는 08–19시의 예시 건수 8·12·16·22·26·30·48·38·32·24·18·12를 표시하며 합계는 전체 저품질 286건이다. 특정 시간은 선택하지 않은 상태다.

- 기본 진입점 `app/page.tsx`를 신규 `components/analyst/analyst-dashboard.tsx`로 연결했다. 기존 Executive 코드는 보존하고 `components/analyst`의 CSS 모듈로 화면 스타일을 분리했다. 설계 시점 9절의 파일 배치 대신 `lib/analyst`에 입력 정규화·집계·위치 출처·선택 상태를 구현했다.

- `data:mdt`는 원본 계약 문자열·독립 통화를 보존하는 v2 추출 경로를 사용한다. `data:overview`는 상세를 하나씩 처리해 현황을 생성하고 원본 버전을 검증한다. `data:all`에는 현황 생성까지 포함했다. 기존 merged/affine 경로는 비교용으로 보존했다.
- 실제 MDT 2026-09-15: 계약 10,250건, 통화 25,548건, 평가 가능 23,085건, 평가 불가 2,463건, 저품질 2,583건. 저품질 중 위치 확보 1,829건·위치 없음 754건으로 원본과 대조했다.
- 분석가 회귀 검사, 실제 데이터 대조, 위치 추정 15개 검사군, Python 47개 검사, TypeScript 검사, 변경 UI의 정적 검사와 제품 빌드가 통과했다.
- 실제 Edge의 1920×1080·1366×768 화면에서 지역→통화→현황 복귀, 시간대 조사, 원본 번호 검색, GNSS 근거, 시점 이동, 늦은 응답 차단, 관측 없는 통화, 실측 전환을 확인했다. 현황 진입의 상세 전체 다운로드는 없고 브라우저 오류는 0건이었다. 실제 캡처는 개인정보가 포함될 수 있어 Git 제외 경로 `outputs/analyst-ui/browser`에만 보관한다.

## 12. 2026-10-26 승인된 UI 후속 개선

사용자가 여섯 개선 항목의 적용을 승인했다. 실제 지역명이 없는 격자에는 안정적인 조사구역 별칭을 주고, 원본 ID·중심 좌표는 설명에 보존했다. 현재 조사 조건과 결과 수를 상단에 모으고 개별/전체 해제, 구역 선택 시 명시 지도 이동, 목록 확장 보기와 고정 머리글을 추가했다. 전체 분석 분모는 유지한다.

시간대 차트는 저품질 건수와 평가 가능 통화 기준 비율을 전환하며, 평가 불가와 0%를 구분한다. 지도 단계색과 숫자 범례는 같은 함수를 공유한다. 계약 분석에는 실제 색상 임계값·결측 범례, 통화 목록 접기, 지도/근거 중심 보기, 핵심 무선값과 원본 대조 그룹을 반영했다.

시간축은 선택 관측 주변 1분/5분 확대, 전체 복원, 다음 조건 관측·Cell 변경·30초 초과 공백 탐색을 지원한다. 원본 관측 index와 실제 timestamp 순서를 유지하고, 확대해도 전체 통화의 이전/다음·키보드·슬라이더 이동은 계속 가능하다. 자정과 긴 공백의 경계 회귀를 포함했다.

위치 모델·원본 좌표·품질 판정·전체 통화 분모는 이 UI 작업에서 변경하지 않았다. 의심 GNSS와 보정된 불확실성의 판정은 별도 위치 품질 개선 설계의 후속 범위다. 이번 작업 기록: [조사 도구 구현 계획](../plans/2026-10-26-analyst-ui-investigation.md).
