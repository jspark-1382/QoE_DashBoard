# 품질 현황 개선 1안 재설계 — 기존 화면 기반

작성일: 2026-11-07 KST. 상태: 구현 후 사용자 전체 화면 비교 피드백 반영. 이 문서는 이전 `voice-experience-improvement-1-design`의 독립 대시보드 설계를 대체한다.

최신 UI 기준: 후보 분석 화면은 원본과 동일하게 조건 → 후보 요약 3개 → 지도/목록 순서다. 아래 초안의 ‘후보 모드에서도 KPI·차트·통화 목록 유지’ 조항은 폐기한다. 전체 현황 지표·수집 현황·차트는 기존 현황 모드에서 표시하고, 후보 통화 목록은 관련 통화 조사를 명시적으로 선택한 경우에만 표시한다.

## 1. 다시 확인한 요청

사용자는 현재 **품질 현황 페이지를 개선**하려고 했다. 기존 화면의 구성과 분석 흐름을 버리고 별도 대시보드를 만드는 것은 요청과 달랐다.

사용자가 이번에 확인한 표시 방식은 다음과 같다.

> ‘개선 1안’에 같은 품질 현황의 개선 버전을 표시하고 원본과 비교.

따라서 개선 대상은 현재 `/qoe/`의 `QualityProposalFour`다. 기존 `기존안` 탭에 연결된 구형 `QualityOverview`를 개선의 원형으로 삼지 않는다. 현재 품질 현황과 개선 1안은 **같은 화면 구성·같은 컴포넌트·같은 기본 분석 조건**을 사용한다. 원본 화면은 비교용으로 유지한다.

## 2. 화면에서 유지할 것과 개선할 것

| 현재 품질 현황의 영역 | 유지 | 같은 자리에서 개선 |
| --- | --- | --- |
| 상단 필터 | 시작/종료일, 전체 기간, 시간, 고객 검색, MOS/Drop, 초기화 | 원본 ↔ 개선 1안 전환 시 선택 조건 유지. 후보 분석에도 실제 산정 기간 표시 |
| KPI 4개 | 전체 통화·MOS 평가 가능·평균 MOS·저품질 통화의 순서와 카드 형태 | 분모를 명확히 하고, 카드 바로 아래 작은 접기 영역에 MDT 연결·GNSS·검토 통과 추정·활용 가능 건수 표시 |
| MOS 점수 분포 | 도넛, 등급 선택, MOS/Drop 전환 | 유효 MOS·전체 CDR·미평가의 분모 설명을 명확히 함 |
| 시간대 그래프 | 누적 막대, 평균 MOS 선, 클릭 탐색 | 현재 기간/고객의 집계와 지도·목록 연계를 일관되게 유지 |
| 고객 체감품질 | 경험·반복·연속의 기존 3행과 클릭 동작 | 반복 통화와 반복 날짜를 구분. 관측일·최대 연속 관측일은 도움말/상세에서 설명 |
| 지도 + 오른쪽 순위 | 기존 지도 위치·크기, 행정동 순위 배치, 전체화면 | 실측/검토 통과 추정/기지국 참고를 구분. 다른 위치 근거를 같은 마커로 묶지 않음 |
| 기존 ‘개선 후보 분석’ 모드 | 현재 페이지 안에 이미 있는 진입 버튼과 지도/후보 목록 | 이 모드 자체를 개선. 실제 기간·시간의 후보, 주변 도트, 선정/제외 이유, 조사 순위를 보여줌 |
| 통화 목록 | 기존 검색·SIP 필터·CSV·통화 선택 | 후보 관련 통화 강조와 관련 고객의 기간 전체 통화 조회를 기존 목록에서 전환 |
| 통화 상세 팝업 | 지도·원본 MOS·Drop·RTP·MDT·원본 통화 링크 | 위치 채택/제외 이유, 반복/연속 정의, 현장 자료 확보 상태를 접기 영역으로 추가 |

새 제목 영역, 별도 조건 입력 폼, 대형 수집률 흐름도, 별도 고객 대시보드, 새 하단 카드 묶음으로 화면을 재구성하지 않는다. 첫 화면에서 기존 KPI와 3개 차트가 보이는 구성을 유지한다.

기존 품질 현황은 후보 모드로 바꾸면 KPI·차트·통화 목록을 숨긴다. 개선 1안에서는 이 맥락을 유지하고 **지도/오른쪽 패널의 내용만 후보 분석으로 전환**한다. 후보를 선택하면 아래 기존 통화 목록과 팝업에서 조사한다.

## 3. 같은 페이지의 두 표시 모드

- 원본 품질 현황: `/qoe/` 또는 `/qoe/?variant=current`.
- 개선 1안: `/qoe/?variant=improvement1`.
- 구현 본체: `QualityProposalFour({variant?:'current'|'improvement1'})`. 기본값은 `current`.
- 두 모드는 `quality-proposal-four.module.css`와 기존 하위 구성요소를 공유한다. 개선 기능만 조건부 적용한다.
- 상단 순서는 현재대로 두고 `기존안` 바로 오른쪽의 `개선 1안`을 위 개선 모드에 연결한다.
- 구형 `기존안` 탭과 `view=overview/contract` 링크는 유지한다. **개선 1안의 ‘원본과 비교’ 대상은 현재 품질 현황**이다.
- 잘못 만든 `/overview-improvement-1`은 향후 구현에서 같은 페이지의 개선 모드로 호환 이동시킨다. 기존의 독립 workspace를 계속 렌더하지 않는다.

## 4. 비교 조건과 필터 의미

현재 품질 현황의 의미를 기준으로 삼는다. 이전 독립 workspace의 필터 규칙을 이식하지 않는다.

- 기간·일별 시간 범위·선택한 복수 고객은 **KPI·그래프·지도·순위·통화 목록 전체**에 적용한다.
- 시간대 클릭, MOS 등급, 고객 경험 그룹, 행정동, 위치 근거, SIP 필터 등은 현재 화면의 탐색 범위를 그대로 따른다. 예를 들어 시간대 클릭으로 상단 전체 기간 KPI를 다시 계산하지 않는 기존 동작은 유지한다.
- 탭 전환에는 기간·시간·복수 고객·MOS/Drop·등급·시간대·경험 그룹·행정동·위치 근거·지도 모드를 전달한다. 선택 통화는 동일 자료와 범위 안에 있을 때만 복원한다.
- 새로고침과 뒤로/앞으로 이동에도 복원한다. 조건을 확인하기 전에 다른 날짜 결과를 먼저 표시하지 않는다.
- 직접 진입의 기본 날짜는 기존 품질 현황과 동일하게 한다. 개선 모드만 전체 5일로 임의 확대하지 않는다.
- 고객 필터가 적용된 상태의 후보 분석은 현재처럼 비활성화하고 이유를 표시한다. 후보는 전체 고객으로 산정한 결과라는 사실을 숨기지 않는다. 후보 관련 고객을 자세히 보는 기능은 후보 상세에서 별도로 제공한다.
- 원본 revision이 다르면 동일 조건 비교로 표시하지 않는다. 계산 대상이 달라진 위치 근거/후보 수는 변경 이유와 함께 보여준다.

## 5. 보고서 피드백의 적용 위치

1. **후보 선정 기준:** 기존 후보 목록/선택 후보 상세에 DBSCAN 100m 이웃 거리, 최소 통화 수, 고객 수, 관측일, 검증일과 조사 순위를 설명한다. 100m를 군집 전체 반경이나 위치 정확도로 표현하지 않는다.
2. **위치 근거:** 지역 후보는 GNSS와 근거를 재현해 엄격 검토를 통과한 3-Site만 사용한다. BYE와 거친 3사이트 위치는 참고용으로 구분한다. 일반 지도·통화 팝업의 기지국 참고 기능은 유지한다.
3. **용어:** 경험 고객, 2회 이상 반복 통화, 인접 통화의 연속 불량, 서로 다른 불량 관측일, 달력상 연속 관측일을 구분한다. 정상·미평가 통화를 삭제하고 연속으로 만들지 않는다.
4. **수집률:** 기존 KPI 아래 접기 영역에서 동일 기간·시간·고객 모집단의 고유 통화 수와 분모를 표시한다. 유효 MOS→MDT 연결 후 GNSS/검토 통과 추정은 병렬 분기로 계산하고 중복 채택하지 않는다.
5. **후보/고객 조사:** 후보 관련 저MOS 통화와 선택 고객의 기간 전체 통화를 기존 표에서 구분한다. 고객의 다른 지역 통화를 후보 구성 통화로 편입하지 않는다.
6. **검증:** 후보 0곳인 하루에도 관련 관측점은 남긴다. 외곽/희소/연결 사슬 검증과 현장·SCAN 자료의 확보 상태는 기존 후보 상세/통화 팝업에서 설명한다.
7. **후속 범위:** 10/30초 MOS, 위치 확보율 확대, NQI/WING 연계는 별도 자료와 투자 검토가 필요한 후속 과제로 남긴다.

현재 엄격 검토 통과 3-Site가 0건이면 0건으로 표시한다. 후보 수 증가나 감소를 맞추기 위해 위치 검토 기준을 완화하지 않는다. 원본 MOS 하나를 복사해 구간 MOS로 만들지 않는다.

후보 계산은 이미 검증한 계산 모듈의 기본 정책을 재사용한다: DBSCAN 이웃 거리 100m, 최소 2통화, 고유 저MOS 고객 3명 이상, 관측일 2일 이상이다. 3일 이상은 마지막 날을 검증일로 남기고 해당 후보의 발견기간 저MOS 고객에 없던 신규 고객 2명 이상의 재관측을 구분한다. 1~2일은 검증 없는 탐색으로 표시한다. 하루는 반복 지역 후보로 승격하지 않고 관측점만 보여준다. 범위가 넓게 이어진 후보는 범위 검토 대상으로 분리한다. 이 값을 맞추려고 후보 수를 고정하거나 검증일을 발견에 사용하지 않는다.

## 6. 데이터 연결과 성능

현재 `loadDataset`/`loadOverview`/`combineDateOverviews`/화면에 필요한 고객 상세 지연 로딩을 유지한다.

이전에 만든 약 207MB의 전체 보고서 JSON을 화면 초기 로딩의 필수 자료로 사용하지 않는다. 검증된 순수 계산은 재사용하되 아래처럼 연결을 바꾼다.

- 수집률은 기존 CDR 목록에 작은 일자별 연결/위치 근거 인덱스를 결합해 계산한다. 완전한 원본 연결 감사가 확인된 경우만 인덱스에 없는 통화를 ‘없음’으로 판정하고, 그렇지 않으면 ‘미확인’으로 남긴다.
- 후보 목록은 기간·시간·원본 버전·정책에 해당하는 **요약 파일**만 읽는다. 좌표·구성원·주변 관측점은 후보 선택 후 상세 파티션에서 읽는다.
- 후보가 0곳일 때의 범위 관측점은 후보 ID를 요구하지 않는다. 이미 읽은 overview의 해당 통화·좌표와 작은 위치 근거 인덱스를 결합해 `buildQualityScopeObservationPoints`로 계산한다. 후보 상세가 없어도 선택 기간의 채택된 저MOS 관측점은 표시할 수 있어야 한다. 근거 인덱스 자체가 미확보면 그 상태를 따로 표시한다.
- 후보 고객의 전체 통화는 기존 overview의 선택 고객 통화와 기존 상세 로더로 얻는다. 전체 CDR·전체 결정 계보를 후보 JSON에 반복 저장하지 않는다.
- 원본 파일별 전체 해시 목록과 전체 감사 결과는 로컬 감사 산출물에 보존하고, 브라우저에는 정책 버전·요약 해시·참조만 전달한다.
- 선택 조건에 해당하는 후보 산출물이 없으면 지도/후보 영역에만 ‘해당 조건 산정 필요’를 표시한다. KPI·차트·일반 통화 목록은 계속 사용할 수 있다.
- 신규 후보 요약 파일은 범위당 1MB 이하를 인수 기준으로 한다. 전체 보고서 다운로드 없이 초기 현황을 볼 수 있어야 한다.

## 7. 이전 구현의 처리

재사용 검토 대상: 위치 검토, 수집률 집합 계산, 반복/연속 지표, 후보 비교, 원본 버전 검증과 관련 경계값 테스트. 기존 UI의 데이터 모델에 맞는 어댑터를 거친다.

계속 사용하지 않을 부분: 독립 `workspace`의 레이아웃·헤더·별도 폼·수집률 중심 배치, 그 화면 전용 CSS, 해당 화면을 여는 상단 링크, 전체 보고서를 필수로 읽는 로더. 새 실행에 사용되지 않도록 연결을 제거한 뒤 참조가 없는 파일과 생성물의 정리 범위를 기록한다. 기존 화면이나 원본 데이터는 정리 대상으로 삼지 않는다.

이번 요청은 **계획 재작성**이다. 기존 실행 화면·실험 파일·서버를 이 단계에서 삭제하거나 교체하지 않는다. 후속 구현에서는 수정된 비교 화면을 먼저 확인한 뒤 잘못 만든 화면과의 연결을 전환한다.

## 8. 완료 판단

- 두 모드의 첫 화면이 같은 KPI 4개·차트 3개·지도+순위·통화 목록 구조다.
- 원본 모드의 화면·수치·주요 상호작용이 변경 전 기준과 같다. 개선 1안의 공통 수치도 같은 모집단에서 일치한다.
- ‘개선 1안’이 같은 품질 현황 페이지의 개선 모드로 열리고, 구형 기존안을 비교 원형으로 착각하지 않는다.
- 복수 고객, MOS/Drop, 시간대, 등급, 행정동, 지도, 목록, CSV, 모달 연계가 유지된다.
- 후보 모드에서도 기존 KPI·차트·통화 목록을 유지하며, 후보 수/일자를 고정하지 않는다.
- 후보만의 오류나 미생성 상태가 기존 현황 전체를 가리지 않는다.
- 207MB 전체 보고서를 가져오지 않고 기본 현황과 후보 목록을 사용할 수 있다.

세부 실행 순서는 [수정 개발 계획](../plans/2026-11-07-quality-overview-improvement-1-revision.md)에 정리한다.

검토 반영: 후보 0곳일 때 선택 가능한 후보 ID가 없다는 점을 확인해 범위 관측점의 계산 경로를 후보 상세 로딩과 분리했다. 현재 화면을 원형으로 삼는 방향과 필터 의미는 검토에서 일치함을 확인했다.
