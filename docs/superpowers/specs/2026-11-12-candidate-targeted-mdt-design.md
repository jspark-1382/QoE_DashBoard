# 후보 구간·종료 사유 분석 및 AI 요청 확인 설계

사용자 승인: 2026-11-12, 직전 검토 방향으로 개발 진행. 추가 MDT 파일 '개포동제외 나머지_MDT.xlsx'를 포함한다.

## 목표
하나의 팝업에서 1 문제 요약 → 2 원인 분석 → 3 원인별 개선 조치·SOP를 유지하고, 각 결과를 실제 MDT 구간·대역 또는 종료 사유 집단에 연결한다. 상단에서 해당 실행의 System/User/전송 자료/응답을 확인한다.

## 분석 원칙
- RTP 손실·지터를 QoE/MOS 원인으로 반복하는 단독 가설을 만들지 않는다. 현상·시간 대조·검증 지표로만 사용한다.
- 넓은 후보라는 사실은 원인이 아니다. 실제 구간 차이를 계산한다.
- 원본에 있는 FC·BYE·Release Cause를 먼저 제시하고 미해석 코드와 미확보 필드를 구분한다.
- MDT 원본의 RSRQ·PHR·RSRP 기준별 비율을 보존하고, 평균만으로 판단하지 않는다.
- POT/대역/측정일별 실제 측정 수와 분포로 조사 위치를 지정한다. 표시 원·25m 해상도를 실제 통화 저하 좌표 정확도로 해석하지 않는다.
- 별도 날짜 배경 MDT와 통화 연결 MDT를 구분한다. Cell/PCI 없는 격자에 최근접 기지국을 책임 셀로 배정하지 않는다.
- 구체적 결과가 없으면 원인 가설 0개를 허용한다. 세 단계 수와 가설 수는 별개다.
- 원인/조치는 서버의 실제 대상 ID와 근거에 연결한다. 확인한 원문과 미확인 사항을 동시에 표시한다.

원본 Drop2: FC9563, BYE102^RTP timeout, REASON H : Drop/V : Rx_RTP_middle_Loss, Release0: Tx Bye. FC9563의 공식 해석은 미등록. SIP/Q.850로 임의 매핑하지 않는다.

## 화면
기존 세 단계와 일반/전체지도 선택·포커스·스크롤 보존. 상단 접힘 'AI 입력·응답 확인': System / User / 전송 데이터 / 응답·검증. 실행 모델·시각·옵션·새 요청/재사용 표시. 요청시 실제 사본을 저장하며 이전 미보관 결과를 재구성된 실제 전송본처럼 보여주지 않는다. 인증키·헤더·.env 전체는 공개하지 않는다.
2단계에서 실제 분석 POT를 지도에 표시하고, 원인 카드와 3단계 조치 카드의 대상·순서를 연결한다.

## 접근 선택
프롬프트만 변경하면 누락 데이터 문제를 해결하지 못한다. 원본 전체를 모델에 넘기면 집계 정확성·크기·재현성이 약하다. 서버에서 관측 차이와 종료 유형을 계산하고 Qwen이 해석과 조치 이유를 설명하는 접근을 적용한다.

## 제약
기존 사용자 작업 트리·추가 MDT 원본을 보존한다. 원본 데이터와 .env를 수정하지 않는다. 실제 망 변경은 없다. 기존 QoE/Drop/군집 정책을 바꾸지 않는다. 로컬 미리보기만 재빌드/재시작한다.
