# 재부팅 후 QoE 실행

프로젝트 폴더의 **`QoE 실행.cmd`를 더블클릭**하세요. 준비된 화면을 실행한 뒤 브라우저에서 아래 주소를 엽니다.

<http://localhost:3001/qoe/overview-proposal-4>

- 이미 실행 중이면 같은 서버를 재사용합니다.
- 실행 창이 닫혀도 화면은 계속 사용할 수 있습니다. PC를 종료하면 서버도 종료됩니다.
- 실행기는 Windows의 별도 실행 경로로 서버와 접속 연결기를 시작합니다. Codex의 명령 실행 창이나 앱 수명에 종속되지 않도록 했습니다. Windows 로그인 자동 실행은 등록하지 않습니다.
- 데이터 생성이나 빌드를 다시 실행하지 않습니다. 이 프로젝트의 `dist`, `node_modules` 폴더를 유지하세요.
- Node.js 22.13 이상이 필요합니다. 필요한 파일이 없거나 다른 프로그램이 포트를 사용하면 실행 창에 이유를 표시합니다.
- 최적화된 로컬 빌드는 `npm.cmd run build:local`로 준비합니다. 데이터 복사를 생략하므로 프로젝트의 `public` 폴더도 유지해야 합니다. 기존 `npm.cmd run build`는 데이터를 포함하는 기본 빌드로 유지됩니다.
- 접속은 이 PC에서만 가능합니다. 오류 로그는 `.tools/qoe-local-server` 폴더에 있습니다.

브라우저를 열지 않고 실행 상태만 확인하려면 프로젝트 폴더에서 다음 명령을 사용하세요.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-qoe.ps1 -NoBrowser
```

## 앱을 닫은 뒤 접속이 끊겼던 원인

2026-11-06 점검 시 화면 서버(3014)는 실행 중이었지만 접속 연결기(3001)는 종료돼 있었다. 연결기 오류 로그에는 예외가 없었고, 이전 실행기는 명령 실행 프로세스에서 `Start-Process`로 직접 자식 프로세스를 만들었다. 명령 실행 환경의 정리 동작과 수명이 연결된 상황으로 판단했다. 종료 이벤트 로그가 없어 앱 종료가 직접 원인이었다고 확정하지는 않는다.

현재는 `start-qoe-service.ps1`을 Windows의 `Win32_Process.Create`로 숨겨 실행하고 그 안에서 두 서비스를 시작한다. 실행용 PowerShell이 종료된 뒤에도 서비스를 유지하며 로그와 포트 소유권 검사도 유지한다. 성공하면 `status.json`을 실제 실행 중인 PID로 갱신한다. 사용자가 직접 Node 프로세스를 종료하거나 PC를 종료하면 서버는 멈추므로 그때는 다시 실행 파일을 더블클릭한다.

`npm run test:launcher`는 별도 테스트 프로세스로 실행기와 Windows 도우미가 종료된 뒤에도 Node가 살아 있고 로그를 기록하는지 검증한다. 테스트는 운영 서버를 종료하지 않는다.
